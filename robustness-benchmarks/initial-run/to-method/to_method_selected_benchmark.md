# to-method: selected benchmark

This report records how the 19 input programs and 100 transformation sites were selected for the initial to-method experiment.

| Input collection | Files reviewed | Selected programs | Selected sites |
|---|---:|---:|---:|
| VerCors `examples/` C inventory | 88 | 16 | 96 |
| Original pilot set | 7 | 3 | 4 |
| Total | 95 | 19 | 100 |

The archived [site scan](selection/site-scan.tsv) contains one row for each of the 88 C files. Its paths match the present `examples/` C inventory. It records positive counts for 25 files and zero for 63. The `note` column concerns that old transformation attempt; it is **not** the original-verification verdict. Nine files with positive counts were excluded: five did not verify in the recorded original runs, and four are expected-error tests whose harness reported success. The five failures also include `pointer_array.c`, which contains expected-error annotations as well as other verification failures.

The scan and exclusion table describe the initial selection, not the latest verification results. A zero count does not establish that a program has no suitable sites if parsing or resolution failed. The exclusion table links the original logs to distinguish these cases. For example, `Challenge2.c` was excluded after its original verification failed in this selection, but was included in the later four-transformation benchmark.

The original verification logs are preserved under [selection/original-verification/](selection/original-verification/). [record-sources.tsv](selection/record-sources.tsv) identifies their archived sources and SHA-256 checksums. The selected-program table below links to the successful original verification logs from the latest recheck. Expected-error annotations can make a test harness report success; such examples are excluded from this verified-input benchmark.

## Selection rules

[ToMethodSites.scala](../../../src/rewrite/vct/rewrite/ToMethodSites.scala) selects a nonempty block below a function body. The selected block cannot contain a local declaration, a scope introducing locals, a nested loop, `switch`, `return`, `throw`, `break`, `continue`, `goto`, `send`, or `recv`. A branch or loop can contain an eligible child block. Verification helper functions such as `__VERIFIER_*` are excluded by function name; there are no benchmark-filename cases. Candidate counts describe these implemented rules, not every theoretically extractable block.
