# to-method: experiment results summary

**19 input programs; 100 distinct sites; 100 ROBUST results; 0 NOT_ROBUST results.** Each row applies to-method once to one site, starting again from the original input. It is not a chain of 100 transformations.

The [selected benchmark](../../initial-run/to-method/to_method_selected_benchmark.md) lists the reviewed files, the 19 selected inputs and the exclusion reasons. [SOURCES.tsv](../../initial-run/to-method/SOURCES.tsv) maps copied inputs to their source programs.

## Latest recheck

This table links only to the latest recheck. Its 79 initial results and 21 continuation results are described in the [run record](to-method-recheck.md). The [verdict table](to-method/verdict.tsv) and [provenance record](provenance.tsv) identify these artifacts. The [initial experiment summary](../../initial-run/to-method/to_method_experiment_results_summary.md) provides the earlier outputs and logs. Both runs record 100 ROBUST results.

## What was verified

The original and transformed verification logs report success for every row. Of the generated helpers, **98 are marked `inline`**. VerCors expands their bodies at call sites before backend verification. **Two helpers use separate contracts:** `3_while_multip` site 0 and `pallas_c_loop_unused` site 0. The mode is visible in each generated C file and in the table. Successful inline cases are not evidence that an independently checked helper contract was generated for them. These results establish the observed behavior for these 100 transformations; they do not establish support for arbitrary C programs.

The implementation and its restrictions are explained in [robustness-changes.md](../../../robustness-changes.md#current-to-method-implementation) and [robustness-files.md](../../../robustness-files.md#to-method-source-map).

Commands are recorded in [run.sh](../run.sh); [run.env](run.env) and the [run record](to-method-recheck.md) describe the execution and consolidation.
